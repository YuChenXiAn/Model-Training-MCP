## 转换规则
1. 生成 Markdown，固定结构：0. 角色与任务；1. 工程约束；2. 业务与时序逻辑；3. 配置与校验；4. JSON 输出；5. 自动测试；6. 工程交付物；7. 验收标准；8. 默认口径与不确定事项。
2. 原业务字段原样保留，特别包括拼写 `linger_peroson_num`，不得无声更名。说明字段冲突和建议默认值，并与已证实规则严格区分。
3. 输入单类 person 时，不得保留鼠类、变化检测、双模型等不属于业务的逻辑。
4. 人员徘徊为**跨帧时间状态任务**：同一人 ID、ROI 持续驻留、计时、丢帧与跨 CID 隔离是必需设计项，单张图无法验证徘徊告警。
5. 输出完整且可解析的 JSON 示例，类型和计数一致：`algorithm_data.is_alert` / `alert_time_s` / `target_count` / `target_info`，`model_data.objects`；不允许重复 key。
6. 明确配置规则的组合方式和阈值边界语义。若原文未定义，标为“建议默认”，不可伪称原文规定。
7. 写出按 P0/P1 分级的可复现用例：人框、ROI、跟踪 ID、时间阈值、数量逻辑、投票窗口、多 CID 隔离、ONNX 输出兼容性与真实图片。
8. 真正实施 EV-SDK 代码之前必须审查具体 SDK 骨架、接口、编译命令和平台 SDK 协议；工程不存在时只交付任务规格，不能虚构可运行的 SDK 项目。
